# 13: Codex system skill quick_validate.py durable upstream fix

## Context

Issue: https://github.com/m16khb-org/issueops/issues/13

The Codex `skill-creator` system skill can fail in a fresh Python environment
when `skill-creator/scripts/quick_validate.py` imports external `yaml` without
PyYAML installed. The local materialized copy under `~/.codex/skills/.system`
is host-managed and can be regenerated by Codex, so direct edits there are not
a durable fix.

## Large Issue Breakdown Gate: no split

근거:
- The issue has one directly executable objective: find and fix the upstream
  distribution path for Codex system `skill-creator` validation.
- The acceptance criteria all validate the same boundary: no undeclared PyYAML
  dependency and no reliance on the materialized `.system` copy.
- The expected implementation boundary is one focused investigation/fix path,
  plus documentation only when the durable source or limitation is verified.

## Plan

1. Reproduce the dependency failure in an isolated Python mode. (done)
   - Use `python3 -S` or an equivalent dependency-isolated command.
   - Verify whether current local materialized `quick_validate.py` passes only
     because of a local patch or user-site dependency.

2. Locate the durable source of the Codex system skill payload. (done)
   - Inspect the installed Codex package, `~/.codex` materialized files,
     vendor import caches, plugin caches, and host metadata.
   - If no local source exists, record that as evidence and identify the
     upstream distribution/reporting path rather than pretending this repo owns
     the fix.

3. Apply the smallest durable fix available in this repository only if a real
   issueops-owned source is found.
   - Candidate behavior: stdlib fallback for simple scalar frontmatter.
   - Non-goal: patch only `~/.codex/skills/.system/.../quick_validate.py` as the
     final implementation.

4. If the durable source is outside this repository, update issue #13 with the
   evidence and recommended upstream action instead of creating a fake local
   completion.

## Findings

- Durable upstream source found:
  `openai/codex/codex-rs/skills/src/assets/samples/skill-creator/scripts/quick_validate.py`.
- Codex embeds `codex-rs/skills/src/assets/samples` through
  `codex-rs/skills/src/lib.rs`, then materializes it into
  `CODEX_HOME/skills/.system`.
- The current upstream file imports external `yaml`; an isolated Python run of
  unpatched marketplace copies fails with `ModuleNotFoundError: No module named
  'yaml'`.
- Local Codex `.system` currently passes because the materialized copy was
  patched locally; that is useful as a workaround but not a durable fix.
- Detailed evidence is recorded in
  `.issueops/research/codex-system-skill-quick-validate.md`.

## Verification

- `python3 -S <quick_validate.py> <skill>` reproduces or verifies the validator
  behavior without user-site packages.
- `find` / `rg` evidence identifies whether `skill-creator` source exists in
  local Codex package, plugin cache, vendor import cache, or repo source.
- `git status --short --branch` confirms source checkout remains clean and all
  work happens in the linked worktree.
- If repo files change, run `git diff --check` and the smallest affected
  focused tests or docs/golden checks.

## Risks

- The actual Codex system skill distribution source may not be present locally
  or in this repository.
- A local PyYAML install can mask the failure, so isolated Python verification
  is required.
- Updating only the materialized `.system` copy would create a false completion.

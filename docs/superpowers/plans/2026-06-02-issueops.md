# IssueOps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a shared IssueOps workflow skill plus minimal issueops state, MCP, and hook routing support.

**Architecture:** Keep the workflow protocol in `skills/issueops/SKILL.md`. Add only lightweight IssueOps state to harness core/CLI/MCP, and keep hooks advisory. Provider-specific GitHub/GitLab issue and PR writes remain agent/tool actions after explicit user approval.

**Tech Stack:** Go CLI/MCP in `cmd/issueops` and `internal/core`; shared Codex/Claude skill markdown under `skills/`; project docs under `.issueops/` and `docs/superpowers/`.

---

### Task 1: Shared `issueops` Skill

**Files:**
- Create: `skills/issueops/SKILL.md`
- Test: skill creator quick validation

- [ ] **Step 1: Write the skill file**

Create `skills/issueops/SKILL.md` with frontmatter:

```markdown
---
name: issueops
description: Run an issue-driven workflow from problem intake through domain grilling, issue creation, planning, TDD/subagent implementation, feedback loops, and PR/MR readiness.
---
```

The body must include these phase gates:

```text
1. Problem Intake: use superpowers:brainstorming.
2. Domain Grill: use grill-with-docs.
3. Issue Contract: draft GitHub/GitLab issue and wait for user approval before creating/updating.
4. Issue-Based Plan: use superpowers:writing-plans.
5. Plan Grill: use grill-with-docs again before implementation.
6. Implementation: use superpowers:test-driven-development and superpowers:subagent-driven-development.
7. Feedback Loop: classify feedback as issue, plan, test, or implementation change before editing.
8. PR/MR Readiness: run repo gates and draft PR/MR after user approval.
```


Expected: success with no metadata or markdown validation errors.

# 160 — 네 사이클이 실측한 규약을 공유 문서에 반영한다

이슈: https://github.com/m16khb/agent-harness/issues/160
사이클: io-37514e35babe
브랜치: `160-docs-upkeep` (base `main` @ 849fa45)

## 문제

#149·#152·#153·#154가 실측으로 세운 규약이 공유 문서에 없다. PostToolUse 훅이
`pending upkeep`으로 `CONVENTIONS.md`·`OPERATIONS.md`·`TESTING.md`를 반복 지목했다.

이 저장소는 라이브러리다. 규약이 코드에만 있으면 그 코드를 읽지 않은 사람이 같은 함정을
다시 만든다. **반복이 이미 일어났다** — #149의 사전 확인이 실환경에서 뚫린 원인(픽스처가
실환경 순서를 재현하지 못함)이 적혀 있지 않아 #154에서 같은 자리를 다시 고쳤다.

## 넣을 것

각 문서의 기존 섹션에 항목을 더한다. 새 섹션을 만들지 않는다.

### CONVENTIONS.md — `Guard 컨벤션`

1. 차단은 왜 막혔는지를 함께 낸다 (#90 발견 4, #154)
2. 해소 경로가 하나로 정해지는 차단만 그 명령을 안내한다
3. 관측 불가와 조건 위반을 다른 슬러그로 구분한다
4. preview는 자기 근거의 강도를 밝히고 실행 가능성도 판정한다 (#99, #152)

### TESTING.md — fake 관련 항목

1. fake는 게이트와 같은 fail-closed 규율을 따른다 (#153)
2. 픽스처가 실환경 순서를 재현하는지 확인한다 (#149)

### OPERATIONS.md — cleanup 절차

1. Turing 리포트는 PR 생성 이전에 커밋한다 (#153)
2. cleanup 명령 순서와 `reflect-completion` 선행
3. 코드를 고친 뒤 설치본을 재빌드한다 (#153 cleanup에서 실측)

## 왜 문서인가 — 코드로 안 되는 것만 담는다

#154에서 진단을 코드에 넣었다. 이 사이클은 **코드가 강제할 수 없는 것**만 담는다.

- "픽스처가 실환경을 재현하는지 물어라"는 판단이지 검사가 아니다
- "리포트를 PR 이전에 커밋하라"는 순서이지 게이트가 아니다(#153이 게이트를 회복 가능하게
  고쳤지만 애초에 만들지 않는 편이 낫다)
- "설치본을 재빌드하라"는 운영 절차다

## 비범위

- `ARCHITECTURE.md` — 훅이 지목했으나 네 사이클은 기존 구조 안에서 필드와 통과 경로를
  더했을 뿐 아키텍처를 바꾸지 않았다
- 문서 전체 재구성

## 검증

```bash
go test ./... -count=1
```

문서 변경이므로 회귀 확인용이다.

# 배선 파일이 지워지면 가드는 테스트만 남기고 사라진다

- Date: 2026-08-28
- Kind: `caution`
- Source: claude-code session
- Summary: legacy hook 표면 제거로 internal/adapter/remoteartifact 전체가 import 0건이 되었고, PR/MR target 브랜치 가드가 조용히 사라진 채 패키지 테스트 16개는 계속 초록이었다.
- Context: 2026-08-27 커밋 2e810e13(refactor(hook)!: remove the legacy hook surface)이 어떤 호스트도 등록하지 않는 PreToolUse 훅과 그 lifecycle guard chain을 지웠다. 훅 제거 자체는 강제 증거가 없어 타당했지만, 가드 구현 패키지 internal/adapter/remoteartifact는 남고 배선 파일 cmd/harness/harnessapp/remoteartifact_wiring.go만 사라졌다. 그 결과 패키지는 모듈 안에서 아무도 import하지 않는 고아가 되었고, 패키지 자체 테스트 16개는 계속 통과해 CI가 매번 가드의 존재를 확인해 주었다. 하루 뒤 자식 Task MR이 부모 작업 브랜치가 아니라 release/stg를 타겟해 열렸고 사람이 먼저 발견했다. deadcode는 main에서 도달 가능한 그래프만 분석하므로 고아 패키지를 아예 보지 못해 이 상태를 잡지 못했다.
- Resolution: PR/MR target 판정을 command policy에 사전 검사로 배선했다. internal/domain/commandparse.ParseRemotePullRequestCreate가 gh pr create / glab mr create argv에서 타겟을 뽑고, internal/adapter/policy가 활성 사이클의 branch_prepare.base_branch와 비교해 pr_target_branch_required 또는 pr_target_branch_mismatch로 거부하며 기대값을 pr_target_branch_expected 경고로 돌려준다. 가드는 함수 포인터 배선이 아니라 직접 import로 묶어 배선 파일 하나가 지워져도 끊기지 않게 했다. 재발 방지로 internal/architecture에 TestProductionPackagesHaveImporters를 추가해, 프로덕션 Go 파일을 가진 패키지가 모듈 안에서 import되지 않으면 실패시킨다. 이 테스트가 remoteartifact와 draftmeta를 잡았고, 그 둘을 지우자 뒤에 가려져 있던 searchrouting까지 연쇄로 드러나 함께 제거했다. 삭제 판정 기준은 도달 가능성이 아니라 테스트가 실데이터를 강제하는지다. VerifyWithGrounded는 main에서 도달 불가지만 augmentcatalog 테스트가 실제 카탈로그를 검사하므로 CI 시점 enforcement로 보아 남겼고, ValidateGitRemoteMatchesIssue는 합성 입력 테스트뿐이라 제거했다.

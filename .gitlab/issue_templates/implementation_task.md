좋은 예시는 문제, 현재 근거, 완료 기준, 비목표, 구현 범위, 검증 명령, 위험을 모두 검증 가능한 문장으로 적습니다.

나쁜 예시는 "좋게 만들기", "필요한 파일 추가", "잘 되는지 확인"처럼 범위와 검증이 모호합니다.

## 문제

해결하려는 문제와 왜 지금 필요한지 적어 주세요.

## 현재 근거

실제 파일, 명령 결과, 로그, 사용자 피드백, 확인된 제약을 적어 주세요.

## 완료 기준

- [ ] 지정된 파일이나 템플릿이 추가 또는 수정된다.
- [ ] 변경 범위가 이 이슈의 비목표를 넘지 않는다.
- [ ] 명시한 검증 명령이 통과한다.

## 비목표

이번 작업에서 하지 않을 일을 적어 주세요.

## 구현 범위

포함할 변경과 분리해야 할 관련 없는 변경을 적어 주세요.

## 검증

실행할 테스트, 빌드, 스모크 체크, 품질 게이트를 적어 주세요.

## 다이어그램

리뷰어가 흐름, 상태 전이, adapter 경계를 더 빨리 이해할 때만 포함해 주세요. 단순 파일 추가나 작은 수정이면 `필요 없음`이라고 적어 주세요.

## 위험과 트레이드오프

남는 리스크, 대안, 선택 이유를 적어 주세요.

## 피드백 기록

사용자 피드백과 요구사항 변경 이력을 적어 주세요.
